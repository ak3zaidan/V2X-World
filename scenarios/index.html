Scenarios¶

A scenario file is the whole input of a run: world, fleet, radio, network, messages, security, credential system, threats, detection, metrics and, optionally, a parameter sweep. Apart from output paths and the explicit CLI overrides (which are recorded), there is no configuration outside it, so a run is reproducible from one file and a seed.

Schema: crates/v2xw-engine/src/scenario/schema.rs (Scenario), current version v2xw/scenario/1. Settings, ranges and their status: configuration.md; every field: the generated reference.

Loading pipeline¶

bytes -> parse (YAML or JSON) -> migrate to the current schema -> merge meta.base -> deserialise -> validate

Modules under crates/v2xw-engine/src/scenario/: migrate.rs (one migrator per schema step), merge.rs, validate.rs. The loader reads files only (no environment, clock or network), so two loads of one file give the same Scenario, and Scenario::content_hash over its canonical JSON is the scenario hash in the manifest. validate returns every problem at once, each as a dotted field plus the conflict, for example radio.tiers.phy: 'high' requires mac 'high' (mac is 'medium').

Overlays (meta.base)¶

A scenario may name a base file, resolved relative to the including file. The merge runs on the untyped document, so "not written" stays distinct from "written as the default":

  • mappings merge key by key, recursively;
  • anything else, including a sequence, is replaced by the overlay;
  • null deletes the base's key.

Most shipped scenarios are short overlays on scenarios/base/city.yaml (a downtown at midday: connected fleet, the US SCMS, eight roadside units at the busiest signalised intersections, detection on every vehicle) or scenarios/base/radio-faceoff.yaml.

Top-level sections¶

Section Configures
schema, meta version; name, description, tags, base
seed the master seed; every RNG stream derives from it (hex or decimal)
time t0, duration_s, mobility_step_ms, des_resolution, warmup_s, credential calendar (real weekly i-periods from the US epoch, or compressed), fast_forward windows
city, world a city of the library, or an explicit world source (kind: osm-xml, sumo-net or procedural with a grid, radial or random generator), buildings, terrain
actors vehicles (demand, equipped fraction, driving models, classes), VRUs, roadside units and their placement and roles, the backend deployment
weather initial condition and intensity; fronts arrive through events
radio rat (dsrc-80211p, lte-v2x-pc5, nr-v2x-pc5, hybrid), tiers per family, model choices, region, channel, MAC and DCC settings
net layer (wsmp, gn-btp), GeoNetworking forwarding, fragmenter, backhaul, cellular Uu, backend network, channel access
messages sets (bsm, cam, denm, spat, map, srm, ssm, psm, vam, cpm), codec_tier (uper, size-model), rates and intervals
security envelope (ieee1609.2, etsi103097), signature, kem, crypto_mode (modeled, real), verification_policy, signer-id policy, pseudonym_change, protocol and its parameters, scms options
nodes hardware profiles for OBUs, RSUs and backend entities; compute tiers
threats attackers, jammers, compromised_rsus and their attack, eavesdropper
detection local detector suites and the MA pipeline
metrics metric ids, or [all]
exporters output exporters (Datasets and exports)
events the timeline
apps V2X applications: fcw, eebl, ima, lta, bsw, pcw, rlvw, glosa
energy emission, fuel and EV energy models and fleet
mobility provider: native (default) or sumo (TraCI)
traffic junction and jam behaviour (right turn on red, rerouting, keep-clear, gridlock), signal control (fixed-time, actuated, NEMA, green wave)
perception sensor suites for CPM senders and the occlusion rule
scale city scale: a microscopic focus region in a mesoscopic city
experiment sweep (dotted path to list of values), seeds, replications

Every optional section, and every optional field at its default, serialises as absent, so adding a field to the schema does not move existing scenario hashes.

The timeline (events)¶

Each item has t, optional until, a type and its parameters; an item may instead fire on a ground-truth condition (when, max_fires, cooldown_s). Types: demand.multiplier, weather.front, attack.wave, outage, param.change, closure, safety.hard-brake, safety.breakdown, safety.cut-in.

events:
  - {t: 60.0, until: 240.0, type: demand.multiplier, value: 1.3}
  - {t: 90.0, until: 270.0, type: safety.breakdown, target: auto}
  - {t: 0.0, type: closure, target: auto}

Cities¶

A scenario says what happens; a city says where. worlds/cities.yaml (compiled into the binary; v2xw cities lists it) names each city's extract, downtown box and jurisdiction (speed preset, right turn on red and similar rules, v2xw_world::jurisdiction). v2xw run <scenario> --city <id>, the server's run.start/scenario.load and the Studio's city picker replace the scenario's world with the city's. City-independent forms make that work (crates/v2xw-engine/src/city.rs):

  • actors.vehicles.demand.rate_veh_per_h_per_lane_km: demand as a density, multiplied by the imported network's driving-lane length;
  • actors.rsu_placement: {count, roles}: units at the busiest signalised intersections;
  • target: auto on a closure or breakdown; at: busiest-junction on a jammer;
  • the clock keeps its local time of day.

Extracts are fetched with worlds/fetch.sh <id> (Overpass API) into worlds/cache/. More: Worlds and maps.

Sweeps (experiment)¶

experiment:
  sweep:
    security.protocol.id: [protocol/scms/camp, protocol/etsi/ts102941]
    actors.vehicles.demand.rate_veh_per_h: [1500.0, 15000.0]
  seeds: [1, 2, 3]
  replications: 2

The plan (v2xw_experiment::plan) is the cross product of the swept values, seed slots and replications in a fixed order, each run's seed derived by hashing from the master seed; the same seed is reused across cells (common random numbers). A swept path must already exist in the serialised scenario, so set an optional field in the base before sweeping it. v2xw experiment run|status|resume executes, journals and aggregates; runs are serial by default (Experiments and sweeps).
