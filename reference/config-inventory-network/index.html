Network parameter inventory¶

Every hard-coded number and every model-struct field in the network stack: v2xw-radio, v2xw-net, v2xw-msg, v2xw-sec and v2xw-node, plus the backend links. Every row says where the number is and either the scenario path that sets it or why it is kept fixed.

The rule used to classify:

  • IMPORTANT means it changes a metric a researcher would study (PDR, CBR, latency, channel load, verification load). These are exposed under the settings contract: a validated scenario field, with its unit, guide text, label and Basic/Advanced level, a default equal to the built-in value, read by the model, and refused where it would do nothing.
  • MINOR means a numerical tolerance, an implementation detail, a protocol encoding, an identifier, or a validation anchor. These are kept.

Protocol constants that a standard fixes (ASN.1 bounds, header sizes, PSIDs, PHY timing) are kept on purpose. A simulator that let them vary would no longer simulate the protocol.

Exposed as scenario fields¶

Each group has a same-seed test in crates/v2xw-engine/tests/network_audit_config.rs. The test runs a baseline and the setting side by side and requires the output to change.

The loader refuses each field where the run would not read it:

  • the sidelink fields on an 802.11p run;
  • a CBR threshold off the 2 dB grid;
  • the reactive fields unless the reactive algorithm runs;
  • the CBF fields when neither forwarding algorithm is cbf, and a minimum at or above the maximum;
  • the SPaT, MAP and CPM intervals when messages.sets lacks that message.
