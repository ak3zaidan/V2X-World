Traffic, world and run parameter inventory¶

The hard-coded numbers and model fields of crates/v2xw-mobility, crates/v2xw-demand and the world's signal synthesis. Each one is either exposed, as a validated scenario field the Studio settings window and the agent pick up from settings.describe, or kept, with the reason. Every exposed field defaults to the built-in value, and the default serialises as absent, so a scenario that does not set it keeps its digest. The loader refuses combinations where a field would do nothing (see traffic_audit_checks in crates/v2xw-engine/src/scenario/validate.rs).

Tests: crates/v2xw-engine/tests/traffic_audit_config.rs runs one same-seed test per group (driver speed and reaction, per-class drivers, junctions, kerbside, GNSS, signal timing), plus the loader refusals and the digest check. With the wiring removed, all six group tests fail.

Limits:

  • The meso tier draws its drivers with the default law, so it ignores the speed and reaction fields. Micro vehicles in a tiered run read them.
  • RTK lowers only the correlated part of the error. The 1.6 m white share stays, so the mean error falls by about 40 %, not to RTK's 0.26 m. To make RTK precise, the white share needs a figure per receiver grade.
  • The right-on-red gap is not scaled by critical_gap_factor.
  • gap_factor is not on the gap-acceptance model card yet.
