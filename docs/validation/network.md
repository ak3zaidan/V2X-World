## Defects found by this suite

| Found by | Defect | Resolution |
|---|---|---|
| ACC-03 | The EDCA backoff countdown restarted from the full draw after every busy period instead of resuming with the slots still owed (EN 302 663 Annex C.4.2 'suspend the countdown'). `EdcaOcbMac::on_cca(Busy)` froze without counting the slots already elapsed, and the engine reported the busy medium only when the node's own timer fired, so the MAC could not know when the medium had gone busy. Effect: longer channel-access delay and a contention process unlike 802.11's under load. | Fixed: `on_cca(Busy)` counts the whole slots elapsed before it freezes, a new `EdcaOcbMac::freeze_at` applies the instant the medium actually went busy, and the engine computes that instant from the arrivals in flight (`Engine::medium_busy_since`). |
| ACC-06 | The reactive DCC state machine jumped straight to the state the CBR mapped to; ETSI TS 102 687 V1.2.1 §5.3 says 'one state can only be reached by a neighbouring state'. | Fixed: `ReactiveDcc::on_cbr` moves one state towards the target per evaluation. |
| ACC-09 | NR-V2X's reselection-counter interval used a floor where TS 38.321 §5.22.1.1 prints a ceiling, ⌈100/max(20, RRI)⌉: at RRI 30, 40, 60-90 ms the counter range was too short (e.g. [5, 15] instead of [10, 30] at 60 ms). | Fixed in `Rri::c_resel_range`. |
| PHY-09 | The sidelink thermal-noise density `cv2x::THERMAL_NOISE_DBM_PER_HZ` was −173.9750935 dBm/Hz; its own documented formula, 10·log10(k·290·1000) with the SI-exact k, gives −173.9751872. A 9.4e-5 dB error, physically negligible, but a constant that disagrees with the formula printed above it. | Fixed: the constant is the formula's value to nine decimals. |
| SEC-01 | The real crypto backend refuses high-s ECDSA signatures (`(r, n − s)`), which FIPS 186-4 and IEEE 1609.2 both accept; OpenSSL emits high s about half the time, so 14 of 32 OpenSSL signatures were refused. | ACC-04 (suite) | The suite's own reference was wrong at high load: Bianchi's Eq. 7 rests on a decoupling approximation that overstates broadcast collisions at small W and large N (0.907 against 0.871 for the exact slotted process at N = 20, W = 16), so the check failed a MAC that was right. | Fixed in the check: the slotted process Eq. 7 models is simulated exactly, independently of the MAC, and held at every N within 0.02; Eq. 7 itself is held where it is accurate (N ≤ 10). |

## What this suite does not yet cover

- IEEE 1609.2.1 linkage-value test vectors: the standard's own vectors were not obtainable; the linkage arithmetic is pinned instead to the CAMP reference implementation's outputs (`crates/v2xw-sec/tests/legacy_vectors.rs`), and SEC-03 checks the revocation decisions it drives.
- The J2735 SPaT and MAP encoders against an independent decoder: the BSM's Part I has one (NET-05) and the ETSI CAM, DENM and VAM have asn1tools (NET-06, which needs `pip install asn1tools` or `NETVAL_PYTHON` naming an interpreter that has it, and otherwise reports a skip); the J2735 ASN.1 modules are not in this repository.
- The SAE J2945/1 CAMP worked examples: the CAMP report was not obtainable; ACC-08 holds the equations to J2945/1's published constants (Ahmad et al. 2019).
- LTE-V2X and NR-V2X block-error curves against the 3GPP link-level results: the crate pins its lookup tables to the published WiLabV2Xsim and Lusvarghi et al. curves in its own tests; this suite does not re-derive them.
- A revoked sender's messages refused after CRL installation in a whole run: covered by `crates/v2xw-engine/tests/security_lifecycle.rs` and `phase2.rs`, too long for this suite's short runs.
