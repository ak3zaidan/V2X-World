# The last ten `77cffb5b` matrix rows and fleet2x re-run on `486c8cba` (2026-10-26)

Branch `worktree-wf_e3e2e994-817-5`, from `486c8cba`. Re-runs every matrix variant that
still carried `77cffb5b` values after rerun-2026-10-25 (§2 "Not run"): `silent`,
`nyc-pilot`, `real-crypto`, `lte`, `nr`, `full-cert`, `backhaul-cellular`, `fleet-half`,
`tls12`, and `fleet2x` for realism V7 ×3, with a fresh `M0` on the same binary (the base
moved since `8becf72a`: the db1 audit wave). Binary: the integrator's release build of
`486c8cba` (copied), second run slot (1.2 GB cap), seed `0xBE7C0001`, `--record-level events
--no-verify` (full-bench.md method). None of the nine 300 s variants was shortened: every row of
them is judged against M0's 300 s + rollover windows (`certs_topped_up` needs the 43,200 s
rollover, `same` rows need M0's own windows). Two pairs were shortened, stated where they
are defined: `fleet2x` as `base-60` → `fleet2x-60` (§1.4) and the TLS pair (§1.3). Every
run but `lte` (1,148 s of wall, §2.3) fit the 10-minute budget.

### 1.3 The TLS pair where TLS acts (`uu-tls13` → `uu-tls12`)

`security.scms.tls` acts only on the packet-level Uu (validate.rs key note: "every
device-to-RA session over a packet-level cellular link"); the realism base's
`cell-capacity-mm1` Uu carries no TCP or TLS, so `tls12` cannot move anything there. Two new
scenarios put M0 on `cellular/uu/packet-pf` (LTE, ISD 500 m, 80 % modems) and change only
the TLS version. Shortened to 0–60 s live and 43,185–43,290 s live (ends at 43,290 s; first cut 43,230 s, corrected in §2.2): the
reports (attack from 20 s) and the rollover top-ups are all a TLS check needs.

### 1.4 fleet2x shortened (`base-60` → `fleet2x-60`)

`lte` on the 300 s base took 1,148 s of wall (×3.6 M0), and a doubled fleet costs about ×4
in receptions, so `fleet2x` on the 300 s base would hold the run slot ~20 minutes. Per the
run budget it runs as a shortened pair instead: `base-60` (M0 with the quarter file's 60 s
first window; rollover window and calendar unchanged) and `fleet2x-60` (1,200 veh/h on it).
V7 needs no misbehaviour flow, so 60 s is enough. The 300 s `fleet2x-req` row stays owed.
