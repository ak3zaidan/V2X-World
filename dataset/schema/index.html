V2X-SCMS-MBD dataset: release schema v1 (draft)¶

Status: draft for review, 2026-11-03. Nothing here is exported yet; §10 lists what the engine must gain first. Supersedes nothing: the legacy ma-dataset profile (08-measurement-and-data.md §6) stays for the internal tools.

1. What the dataset is¶

Every run is published as two observer views of the same traffic plus the answers:

View Who sees it One row is Closest existing dataset
local each vehicle's OBU a message it received, a check that fired, a report it filed VeReMi, VeReMi Ext, NextGen
global the Misbehavior Authority a report it decrypted, a decision, a CRL entry DARE (the only report-level set)
truth nobody in the system who really sent what, which attack, what happened downstream VeReMi GroundTruth file

The same message can be followed from the air, to a neighbour's check, to the report, to the MA's decision, to the CRL, to the moment neighbours stop trusting the attacker. No existing dataset links those steps.

2. Lessons from the existing datasets¶

Dataset Format What we keep What we fix
VeReMi 1.0 (2018) JSON per receiver (type 2 own GPS, type 3 received BSM) + GroundTruthJSONlog per-receiver layout; truth in a separate file joined by message id sender is the real module id inside a receiver file (a label leak)
VeReMi Ext (2020) same, sliced, -A<code> file names, F2MD codes 0–19 the attack codebook, kept as a crosswalk column senderRealId; the attack code in the file name; random-message splits
VeReMi NextGen (2026) JSON → Parquet; receiver and sender blocks inline; 50/10/40 split Parquet; a held-out area for testing; the receiver's own state on each row sender_id and attacker written inline next to the features; no security fields; no report or MA layer
DARE (2020) one JSON report: Metadata, Messages (evidence), Checks (scores) report = metadata + evidence + check scores senderRealId/reportedRealId inside the report; invented format; no revocation, so no outcome
SPADE (2026), CARLA-V2X-MBD (2026) CSV per record, perception features inline receiver-side context (RSSI, receiver pose) no PKI at all; perfect perception; labels inline

Three rules follow:

  1. No answer inside an observer file. Truth lives in truth/. A linter refuses the release if any local/ or global/ column is ground truth.
  2. Join keys are computed from the bytes. Any party holding a message can compute its digest, so the key reveals nothing a real observer could not learn (§5).
  3. Splits are by run, never by message. Random message splits put one car's neighbouring BSMs in train and test, which inflates VeReMi scores.

3. File layout¶

v2x-scms-mbd/
  README.md                         dataset card (Hugging Face YAML header + datasheet)
  croissant.json                    MLCommons Croissant metadata (with RAI fields)
  schema/<table>.json               columns, types, units, visibility, description
  runs.parquet                      one row per run (§4)
  local/{ego,rx,checks,reports,pki}/split=<s>/run=<id>/part-*.parquet
  global/{reports,decisions,crl}/split=<s>/run=<id>/part-*.parquet
  truth/{devices,pseudonyms,transmissions,receptions,reports,timeline,app_effects}/...
  ml/{local,global}/split=<s>/...   flat, labelled training tables (§8)
  compat/veremi/<run>.zip           VeReMi Ext JSON per receiver + ground truth
  compat/dare/<run>.zip             DARE-style report JSON + a separate id file
  wire/{rx,reports}/...             raw signed bytes (full tier only)
  scenarios/<run>.yaml              scenario + seed: regenerates the run exactly

Format. Apache Parquet, zstd, row groups around 128 MB, files at most 1 GB. Lists and structs are native Parquet types, never JSON strings, so the Hugging Face viewer can filter on them.

Conventions. - Times are int64 ns since run start (*_ns); runs.t0_utc anchors them. - On-wire clocks are kept raw: 1609.2 generation_time_us (TAI µs since 2004) and J2735 sec_mark_ms. - Positions come twice: lat_deg/lon_deg as broadcast, and x_m/y_m in local ENU metres from runs.origin_*. - Units are in the column name: _m, _mps, _mps2, _deg, _dbm, _bytes.

Tiers. - mini: a handful of runs, under 500 MB, for the viewer and a quick start. - standard: every run, without wire/ and true kinematics. - full: everything.

4. runs.parquet¶

One row per run. It is the only place experiment settings appear, so a model can't read them off the rows.

Column Example Notes
run_id r0007 partition key everywhere
split train train / validation / test, assigned per run
heldout_attacks [FakeHazard] attacks absent from train, for zero-day tests
city, world_source manhattan, osm
t0_utc, duration_s, origin_lat_deg, origin_lon_deg
vehicles, equipped_fraction, demand_veh_per_h
rat, bsm_rate_hz dsrc-80211p, 10
scms_mode in-loop in-loop / abstracted / off, for paired comparisons
calendar real or compressed with calendar_factors (shuffle window, CRL cadence)
local_suite, ma_policy sm-mbr-us, device-k(k=3,w=3600s)
attacker_fraction, attack_mix 0.10, [{id, fraction, from_s, to_s, params}]
instrumented_receivers 25 §6.2
engine_version, git_sha, scenario_hash, seed regeneration

5. Identifiers¶

Key What it is Who can compute it Appears in
spdu_digest first 8 bytes of SHA-256 over the signed message (1609.2 SPDU) anyone holding the message local, global (evidence), truth
cert_id the signing pseudonym certificate's HashedId8 (1609.2) anyone holding the message local, global, truth
report_id first 8 bytes of SHA-256 over the signed MBR reporter, MA local, global, truth
la_link opaque token, equal for two certificates of one device the MA, only after asking the Linkage Authorities global (nullable), truth
receiver_ref opaque id of the OBU that wrote a local row that OBU local, truth
rx_id unique id of one reception row — local, truth
tx_id, device_id the engine's transmission and device ids oracle only truth only

A verbatim replay has the same bytes, so it has the same spdu_digest as the original. That is real: the receiver also can't tell them apart from the bytes. Truth resolves it per reception (truth/receptions.rx_id → tx_id).

6. Local view (what an OBU knows)¶

6.1 Tables¶

local/ego: the receiver's own state at 10 Hz (VeReMi type 2). run_id, receiver_ref, t_ns, x_m, y_m, lat_deg, lon_deg, speed_mps, heading_deg, accel_mps2, pos_accuracy_m, own_cert_id

local/rx: one row per message the receiver decoded (VeReMi type 3, extended).

Group Columns
keys run_id, receiver_ref, rx_id, t_rx_ns, spdu_digest
radio rssi_dbm, cbr (receiver's channel busy ratio), size_bytes
security psid, cert_id, signer_kind (digest or certificate), issuer_id, verify_result (ok, bad_signature, expired, not_yet_valid, on_crl, unknown_issuer, not_checked), verify_latency_us, generation_time_us
BSM content msg_type, msg_cnt, temp_id, sec_mark_ms, lat_deg, lon_deg, x_m, y_m, elevation_m, pos_accuracy{semi_major_m, semi_minor_m, orientation_deg}, speed_mps, heading_deg, accel{long, lat, vert, yaw_rate}, brakes, transmission, length_m, width_m, event_flags
receiver context ego_x_m, ego_y_m, ego_speed_mps, ego_heading_deg (copied from ego, as NextGen does), range_m (computed from the claimed position)

Other message types (SPaT, MAP, CPM, DENM-like hazard) use the same keys and security group. Their content goes in local/rx_<type> tables.

local/checks: one row per check result on a received message. run_id, receiver_ref, t_ns, rx_id, cert_id, suite, check, fired, score, excess - suite is one of: - sm-mbr-us: the deployed US CV-pilot checks: ConstantPosition, RandomPosition, MaxSpeed, MaxAcceleration, BrakeAcceleration, Distance; - research: the 17 legacy checks, such as positionSpeedInconsistency, headingInconsistency, staleOrReplay, sybilCoLocation, beaconFrequency, mapOffRoad and kalmanConsistency; - ts103759: the ETSI set, including the perception cross-check and CPM consistency. - The optional wide table local/check_scores holds one row per reception with one column per check. It is DARE's Checks block.

local/reports: every MBR this OBU created, and what became of it in its store. run_id, receiver_ref, report_id, t_created_ns, subject_cert_id, mbr_type, subtypes, evidence_spdu_digests[], size_bytes, fate (uploaded, evicted, expired, pending_at_end), t_uploaded_ns, path (cellular / rsu_relay), weight_at_upload

local/pki: the OBU's own credential life. run_id, receiver_ref, t_ns, event (enrolled, batch_downloaded, pseudonym_change, crl_downloaded, download_refused), cert_id, crl_series, crl_number, crl_entries, bytes, latency_ms

6.2 Size control¶

A sample 40-car, 70 s run produced 27,854 transmissions and 164,980 receptions: 58 MB as VeReMi JSON, about a tenth of that in Parquet.

At 200 cars, 10 Hz and around 30 neighbours, one hour is roughly 200 M reception rows. So local/rx and local/ego are written in full only for instrumented_receivers randomly chosen OBUs per run, listed in runs. checks, reports and pki are written for every OBU, because the MA side depends on all of them.

7. Global view (what the MA knows)¶

global/reports: one row per MBR the MA decrypted. The fields are the US CV-pilot report's (SM-MBR v1.0 and its ASN.1 v1.1: EeMaApplicationSpecificMisbehaviorReport, Psid20Mbr, SignedBsmsWithCertificate), decoded.

Group Columns
keys run_id, ma_id, report_id, t_received_ns
report header generation_time_us, generation_location{lat_deg, lon_deg, elevation_m}, psid (0x20), reporter_cert_id
accusation subject_cert_id, subject_issuer, mbr_type (1VInconsistent, Implausible, ObsImplausible), subtypes[{code, name, params}], nonstandard_triggers[] (research-suite checks with no SM-MBR code, flagged)
evidence evidence[{spdu_digest, generation_time_us, sec_mark_ms, msg_cnt, lat_deg, lon_deg, speed_mps, heading_deg, accel_long_mps2, brakes, pos_accuracy_m}], evidence_start_us, evidence_end_us
MA processing set_aside (null, or unverifiable / time_implausible), la_link (null until the policy asks the LAs), la_link_t_ns

The MA never learns the reporter's enrolment identity. The RA authenticates the upload but can't read it. So no reporter device id appears here.

global/decisions: one row per MA decision. run_id, ma_id, t_ns, subject_kind (pseudonym / device), subject_cert_id, la_link, decision (revoke, dismiss, monitor), rule, report_ids[], n_reports, n_distinct_reporters

global/crl: what the MA caused to be published. run_id, t_issued_ns, crl_series, crl_number, entry_kind (linkage_seed / hash_id), la_link, i_period, t_effective_ns

8. Truth (the answers)¶

Table Key Content
truth/devices device_id class (vehicle / RSU / VRU), provider, GNSS class, label (benign / faulty / malicious), attack_id, attack_params, attack_start_ns, attack_end_ns, joined/left times, la_link, receiver_ref if instrumented
truth/pseudonyms cert_id device_id, validity window, first and last use
truth/transmissions tx_id device_id, spdu_digest, label, attack_id, family, crosswalk codes (veremi_ext_code, veremi1_code, nextgen_name, dare_name), fields_falsified[], magnitude, true x_m, y_m, speed_mps, heading_deg, accel_mps2 at transmission, the sender's honest error (gnss_error_m, fix_to_stamp_ms)
truth/receptions rx_id tx_id, sender device_id, label, true distance
truth/reports report_id reporter and subject device_id, subject_label, verdict (true_accusation / false_accusation), store fate, arrival at MA
truth/timeline device_id per misbehaving or falsely accused device: attack start, first falsified message, first local detection, first report created, uploaded, at MA, decision, CRL published, CRL at first / median / 95th-percentile neighbour, last malicious message accepted. That is the "how long a bad actor stays trusted" breakdown.
truth/app_effects row warnings an application raised because of a falsified or faulty message (false FCW, EEBL, IMA, RLVW): app, receiver, tx_id, severity, driver_reaction
truth/kinematics (device_id, t_ns) 10 Hz true state, full tier only

Labels exist at five levels: 1. message: label, attack_id; 2. pseudonym; 3. device; 4. report: true or false accusation; 5. outcome: correct revocation, wrongful revocation, or missed attacker. The outcome is derived from devices and global/decisions.

faulty is a first-class label: an honest device whose data is wrong beyond specification (GNSS error, timestamp lag). DARE's "malfunctions" are the precedent. It is the class Paper 1 measures.

ml/ tables are convenience copies for people who only want to train: - ml/local: local/rx joined with truth/receptions.label and attack_id; - ml/global: global/reports joined with truth/reports.verdict.

They are clearly named as joined, the same way NextGen ships its rows. The local and global folders stay clean.

9. Attacks¶

The engine's catalogue: 46 named, 43 runnable today (crates/v2xw-threat/src/catalog.rs). The VeReMi-Ext code is filled in only where the behaviour matches F2MD's (dataset/veremi.rs); anything else exports as 1024 (unnamed).

Family Attacks VeReMi-Ext / NextGen / DARE closest Where it shows
Position ConstPos, ConstPosOffset, RandomPos, Teleport, SineWavePos, SlowDrift, AlongRoadOffset 1, 2, 4 / constantPositionOffset, randomPositionOffset / position malfunction local plausibility
Speed ConstSpeedOffset, RandomSpeed, StopAndGo 6, 7 / constantSpeedOffset, randomSpeedOffset, suddenStop local plausibility
Heading ReversedHeading, HeadingOffset – / reversedHeading local plausibility
Inconsistent state PosSpeedInconsistent, PosHeadingInconsistent, EventualStop 9 / suddenStop / sudden stop local consistency
Timing DelayedMessages, OutOfOrder, DataReplay 12 / timeDelayAttack, dataReplay / delayed, data replay local timing
Identity Sybil, GhostVehicles 16 / trafficCongestionSybil / Sybil, traffic congestion local and MA (one la_link, many certificates)
Credentials InvalidSignature, ExpiredCert, NotYetValid, WrongRegionCert – security layer (verify_result)
Flooding DoS, DoSRandom, Disruptive, OversizedFlood 13 / dosAttack / DoS, disruptive radio and CBR, rate
Application FakeHazard, VruImpersonation, VruPositionSpoof, FakeCpm – applications and perception cross-check
Suppression and relay SelectiveDrop, RelayReplay – / dataReplay (partly) reception gaps, duplicate digests
Jamming ConstantJamming, ReactiveJamming, RandomDutyJamming – radio only (no messages to label)
Compromised RSU FalseCrl, SuppressForwardedReports, PoisonForwardedReports (FalseSpat, FalseMap and FalseCtl declared, not yet driven) SPADE's classes once SPaT is driven PKI, report path
Against the MA ReportPoisoning, BenignClassMimic (evasion) – global only
Privacy PrivacyObserver (passive tracker; labels tracking success, not messages) – truth only

Benign faults (label faulty): GNSS error classes, fix-to-stamp lag, smoothing artefacts. They are set per device class in the scenario.

To add for full coverage: - NextGen: feignedBraking, accelerationMultiplication, positionMirroring, zeroSpeedReport. - VeReMi Ext: uniform RandomPos (4), ConstSpeed (5), neighbour DataReplay (11), DoSDisruptive and the Sybil combinations (15, 17–19). - SPADE: wire FalseSpat and FalseMap. RLVW and GLOSA already consume signed SPaT and MAP (v2xw-node/src/apps.rs), so the validator note refusing them is stale.

Each is one model in the catalogue. Every run in the loop gets the full downstream chain for free.

10. Quality gates (each must be shown able to fail)¶

  1. Leakage linter: no truth column in local/ or global/. It exists as dataset/leakage.rs; extend its key list to this schema.
  2. Shortcut audit: a classifier trained on metadata only (cert_id statistics, message rate, size, msg_cnt) must score near chance on attacks whose definition isn't rate or size. VeReMi's message-rate shortcut is the precedent (veremi-audit).
  3. Join completeness: every global/reports.evidence[].spdu_digest resolves in truth/transmissions, and every rx_id in truth/receptions.
  4. Grid scan: floats on their declared grid (dataset/grids.rs).
  5. Manifest: SHA-256 per file. Runs regenerate bit-for-bit from scenarios/ plus git_sha.

11. Publication¶

  • Hugging Face is the primary host. Each table is a config, and each config's train / validation / test splits are data_files globs over the split= partitions. The viewer and SQL console work on every config except compat/ and wire/ (zips and binaries). Use load_dataset("<org>/v2x-scms-mbd", "global_reports").
  • Zenodo holds the frozen version: a DOI, the compat zips, the full tarballs. It mirrors the same tag.
  • Licences: CC-BY-4.0 for data, the same as VeReMi NextGen. The engine's licence for code.
  • The card follows Datasheets for Datasets. DATASHEET.md (dataset/datasheet.rs) supplies its sections. Croissant goes beside it.

12. What the engine must gain first¶

  1. A dataset exporter on v2xw run. Today DatasetWriter is called only by tests. A run writes raw channel dumps that mix views; for example, ma_report carries the reporter's node id.
  2. local/rx with the security group. Join phy.rx, node.verify and node.tx content. The VeReMi exporter drops these fields.
  3. spdu_digest and report_id from the real bytes. Add truth/receptions.
  4. Instrumented-receiver sampling (§6.2).
  5. Native list and struct columns. subtypes and spans are JSON strings today.
  6. The DARE compat writer.
  7. Streaming export. A 40-car, 70 s run hit heavy.sh's 4.5 GB cap in the JSONL stage.
